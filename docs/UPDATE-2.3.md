# Prospekt DJ 2.3 BETA — interface and library update

This is a BETA release. The implementation follows the supplied update scheme; reference screenshots guide behavior and layout rather than supplying application code.

## Decks and cue workflow

- Larger 148×174 information-jog panels, with a 144-pixel face and animated rim ticks/arc, show effective BPM (two decimals), signed pitch, the actual ±50% pitch range, source elapsed/remaining time and VINYL/JOG status. The rim marker follows source position; transport, mouse jog and existing MIDI controls remain connected to the engine. The light theme uses a light inner platter.
- Each jog has an adjacent vertical **PITCH BEND** spring fader (±8%) in a graphite panel with a gray outline matching the library. It returns to zero on release/focus loss, preserves the base tempo setting and combines safely with the existing ± buttons / keyboard bend. The central channel faders have 88-pixel travel and larger grab handles; the crossfader is 156 pixels wide.
- Compact Hot Cue pads (at most 64×28 logical pixels each) form two rows of four. A set pad shows its real source time; an empty pad shows `—:—`. Click sets/recalls, Shift+click erases. Recall preserves playing/paused state. F1–F8 operate on the focused deck, including when another pad mode is selected; shortcuts are suppressed during text editing.
- One shared palette identifies slots 1–8: `#FF292E`, `#DE713B`, `#008BF7`, `#FAD83B`, `#00FF00`, `#FB40AA`, `#40F9FB`, `#BE78FF`. The palette is shared by pads, overview flags and zoomed waveform flags, independently of cue order in time.
- Waveform flags use source seconds. Tempo changes do not move stored cues. Hover shows the number and exact time; click recalls that cue rather than seeking under it. Overlapping flags open a cue chooser. Main CUE and playhead remain separate. Waveforms continue using actual decoded RGB frequency bands and the beat grid/loop shading.

## Crates, folders and Unicode

- The sidebar is resizable. Expansion and selected scope are saved with settings. Existing flat crates migrate as top-level crates, retaining IDs, membership, names and order. Parent scopes include descendant memberships without duplicating tracks.
- Right-click a crate to create a subcrate, rename it, add the selected track or remove the crate. Removing a parent lifts its children one level; music files are untouched. Track menus still support membership in multiple crates and catalog removal.
- The name dialog has an **Emoji** picker. It inserts at the remembered caret/selection; keyboard paste also works. Polish accents, repeated emoji, variation selectors, skin modifiers and ZWJ sequences are preserved verbatim in JSON.
- **Color emoji:** 3,846 unmodified 72×72 Twemoji 16.0.1 PNGs are bundled in `assets/emoji`, licensed CC BY 4.0 with attribution and original notices in `licenses/twemoji`. They work offline in the picker, crate/folder labels and the live name preview. Unicode grapheme clusters map to the matching image, including supported ZWJ, variation-selector, flag and skin-tone sequences. Original text is not replaced in storage. `src/emoji.rs` keeps at most 128 small icon textures. The native text-edit caret remains ordinary text, with a color preview immediately below; characters outside the artwork atlas use the bundled font fallback.
- Real home/music/mounted locations and imported roots appear separately from virtual crates. Directory reads run on a worker, 512 subfolders per page; **Load more folders** fetches the next page. Symlink children are not followed, preventing loops. A context menu imports the folder or retries a listing; permission/disconnection errors appear in the tree. Folder selection filters indexed tracks; expansion alone does not import an entire drive.

## Artwork strip and online artwork

- The horizontal, virtualized cover strip follows the same filter/sort order as the table. Click selects/reveals a row; row/keyboard selection reveals the cover. Double-click loads the focused deck without starting playback. Hide it in Settings → General.
- Artwork is read/decompressed away from the UI/audio threads. Selection and late results are keyed by a SHA-256 identity containing path, file size/mtime, title, artist, album, version and tagged MusicBrainz IDs, never a transient row number. Images are shared between strip/decks. The GUI keeps at most 128 thumbnail textures; worker queues are bounded (32 local tasks, 16 online tasks).
- Priority: a valid embedded picture, then a cached manual/downloaded match, then online lookup, then a neutral placeholder. A fresh tag read precedes downloaded cache access. Embedded pictures added later take precedence after metadata refresh.
- **Online lookup is enabled by default**, as requested. Settings → General → **Download missing artwork** disables it. MusicBrainz receives artist/album/title/version and public MusicBrainz IDs; Cover Art Archive receives a release ID. No audio, directory paths, favorites or crate names are transmitted. When a title tag is missing, the catalog title may come from the filename stem. Downloads never modify music tags. Flatpak requests network access for this feature.
- Tagged release/recording IDs are used before searching. Otherwise artist/album (or artist/title without an album) is searched. Matching requires exact normalized artist/title/version and album where present, a high search score and one unambiguous release. Release tracks are checked before fetching `/release/{id}/front-250`. Multiple editions, compilations with different artist credits and uncertain remixes can remain unmatched deliberately.
- A single online worker serializes requests with a minimum one-second interval. A descriptive versioned User-Agent identifies this project. Requests have a 10-second timeout, bounded redirects/responses and up to three attempts for HTTP 429/503, honoring numeric Retry-After (capped at 30 seconds). Offline failures are quiet status text, not repeated dialogs.
- Thumbnail records persist in `covers` beside settings. Valid positive records last a year; missing/ambiguous matches last a day, transient failures ten minutes. Public HTTP metadata/image responses are shared by URL for a day, avoiding repeated album requests across tracks/restarts. Image bytes are shared by content hash. Metadata changes produce a new track identity.
- Right-click a row/cover → **Artwork**: choose a local PNG/JPEG/WebP, reject a wrong match, or retry a lookup. Rejection persists and suppresses automatic return of the same assignment; retry explicitly permits a new lookup. **Clear downloaded artwork** removes online/negative/HTTP caches while preserving manual choices and rejection records. An enabled online lookup can fetch covers again afterward.
- Images are limited to 8 MiB, 4096×4096 input pixels and a bounded decoder allocation; thumbnails are at most 160×160. Cache write failures do not prevent the current session from displaying a downloaded image. The app does not claim that downloaded cover images share the application's source-code license.

## Compact layout based on the supplied arrangements

Track metadata and small 2×4 cue pads sit toward the outer deck edges; larger jogs sit beside the central mixer. A compact header leaves room for stacked waveforms directly below the decks. FX, sampler and full EQ/mixer remain available from their tabs; they start collapsed in fresh settings, while saved user choices are preserved. BPM's context menu exposes TAP, analysis and ×2/÷2 controls. The lower area contains the folder/crate tree, cover strip and table, with selected-track art/metadata on the right in wide windows (optional in settings). At narrow widths the preview is hidden and the table scrolls horizontally.

## Library table and settings

Graphite zebra rows (`#111111` / `#1B1B1B`), full-row selection/hover, fixed headers and virtual rows improve readability. Columns include favorite, number, title, artist, album, tagged remix/version, genre, BPM, KEY, duration, bitrate and A–D loading controls. Narrow windows have horizontal column scrolling. BPM/time sorts remain numeric. Tagged musical/Camelot keys have a separate harmonic palette; missing keys stay unknown, with no fabricated harmonic analysis. Settings can switch Camelot display and cover strip visibility. Logo, BETA notices, 2/4-deck mode, effects, sampler, recording and existing language settings remain available.

The performance panel can be resized vertically. At 1280×720 or high scaling, use its vertical scrollbar to access the lower waveforms/effects/decks while retaining room for the library; the **Library** header button expands the browser. This release does not promise that every control fits simultaneously on a small screen.

## Validation

Local Linux checks: `cargo fmt --all --check`, `cargo clippy --locked --all-targets -- -D warnings`, and `cargo test --locked --all-targets` with ALSA null / FFmpeg enabled. The suite includes transport/cue behavior, metadata queries, legacy crate migration, Unicode edits/round trips, harmonic keys, folder errors/symlink loops, verified/ambiguous/remix/offline cover matching, cache TTL/rejection/manual restart/embedded precedence, stale response suppression, rate/backoff policy and font glyph coverage. Artwork tests use fixtures/fake transport; they do not rely on the public services or certify their availability.

Native GUI checks and screenshots use Linux/Xvfb, generated demo audio and original synthetic cover fixtures; they are not photographs of a hardware performance. Screenshots cover 1920×1080, 1280×720, 2/4 decks and the emoji editor. See `TESTS.md` for final build/package results. Physical MIDI hardware, real headphone routing and end-to-end latency were not tested in this environment.

Official API references: [MusicBrainz API](https://musicbrainz.org/doc/MusicBrainz_API), [rate limiting](https://musicbrainz.org/doc/MusicBrainz_API/Rate_Limiting), [Cover Art Archive API](https://musicbrainz.org/doc/Cover_Art_Archive/API).
